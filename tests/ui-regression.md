# Проверка интерфейса FERMA

Проверять через браузер на отдельной тестовой базе. Реальные ключи не заменять,
социальные публикации для проверки интерфейса не отправлять.

1. Создать профиль. Изменить имя, сохранить, закрыть и открыть снова: новое имя
   должно отображаться в заголовке, списке профилей и редакторе публикации.
2. У поля «Название профиля» проверить рамку 1 px, высоту не меньше 40 px и
   горизонтальные отступы 12 px. Проверить обычное состояние и фокус.
3. Открыть настройки ключа при размерах окна 574×824 и 390×844. Заголовок и
   нижние кнопки остаются видимыми, прокручивается только содержимое. У самого
   dialog нет горизонтального или вертикального переполнения.
4. Свернуть ключ. Обновить соцсети: видны состояние загрузки и результат либо
   понятная ошибка; список не очищается при сетевом сбое.
5. Создать черновик, загрузить изображение, сохранить, открыть снова:
   профиль, название, подпись и выбранный файл сохранены. Изменить и сохранить.
6. Открыть планирование без выбранных сетей: показано, что исправить,
   кнопка отправки отключена, доступен возврат в редактор.
7. В медиатеке открыть загруженный файл и проверить его фактическую загрузку
   (naturalWidth/naturalHeight для картинки), затем назначить в публикацию.
8. Проверить поиск с результатом и без, сброс фильтров, список/карточки,
   переходы между разделами и обновление страницы с сохранённым разделом URL.
9. На мобильном экране проверить редактор, медиатеку, настройки и нижнюю навигацию.

Серверные сценарии, включая ошибки провайдера, сохранность ключей, владельцев,
статусы и повтор отправки с тем же Idempotency-Key:

```powershell
node --test tests/*.test.mjs docker/gateway.test.mjs
npx tsc --noEmit
```

Успешный ответ тестового провайдера не подтверждает публикацию в реальной
соцсети. Для такой проверки необходим подключённый аккаунт Zernio и отдельно
согласованный материал.
